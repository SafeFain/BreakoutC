# Android project (prebuilt .so mode)

This project is based on the official SDL3 `android-project` template, adapted so that **SDL3, SDL3_ttf, and FreeType are linked statically into `libmain.so`**. Gradle only assembles the APK (Java launcher, resources, and assets); no `externalNativeBuild` is used.

## Layout

```
android-project/
├── app/
│   ├── build.gradle          Prebuilt mode (no externalNativeBuild); compileSdk 35, minSdk 29
│   └── src/main/
│       ├── AndroidManifest.xml   Landscape lock (sensorLandscape), SDLActivity
│       ├── assets/fonts/         Bundled subset font (APK assets, read through SDL_IOFromFile)
│       ├── java/org/libsdl/app/  Official SDL Java launcher (modified to load only "main")
│       └── res/                  Resources (app name: Neon Breaker)
├── build.gradle / settings.gradle / gradle.properties / gradlew
└── README.md (this file)
```

## Build steps

### 1. Cross-compile libmain.so

```bash
# Prerequisite: the NDK is unpacked into tools/android/android-ndk-r27c
# and the SDL sources are prepared by tools/android/fetch-deps.sh
tools/android/build-android.sh              # defaults to arm64-v8a, API 29
tools/android/build-android.sh armeabi-v7a
tools/android/build-android.sh x86_64
```

Output: `build-android/libmain.so`. The CMake `ANDROID` branch builds SDL3, SDL3_ttf, and the vendored FreeType via `add_subdirectory`, then compiles the game sources into `libmain.so`.

### 2. Copy the library into the project

```bash
mkdir -p android-project/app/libs/arm64-v8a
cp build-android/libmain.so android-project/app/libs/arm64-v8a/
```

`android-project/app/libs/` is ignored by Git, so every checkout must build (or otherwise provide) `libmain.so` before assembling an APK.

### 3. Assemble the APK (Android Studio or the Android SDK)

Open `android-project/` in Android Studio, or use the command line:

```bash
cd android-project
./gradlew assembleDebug
# Output: app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## Build dependencies

Everything under `tools/android/` is fetched by `tools/android/fetch-deps.sh` (or can be unpacked manually):

- `android-ndk-r27c/` — NDK toolchain
- `SDL-release-3.2.10/` — SDL3 sources
- `SDL_ttf-release-3.2.2/` — SDL3_ttf sources (its `external/freetype` tree is filled in by the fetch script)
- `freetype-VER-2-13-3/` — FreeType sources used by the static SDL3_ttf build

## Bundled font

- File: `assets/fonts/NotoSansSC-Bold-subset.otf` is the canonical subset (~113 KB), generated by `tools/make_font.py`.
- Packaging: Gradle includes `app/src/main/assets/` in the APK; the Android copy lives at `app/src/main/assets/fonts/`.
- After regenerating the font, copy it into the Android assets:
  `cp assets/fonts/NotoSansSC-Bold-subset.otf android-project/app/src/main/assets/fonts/`
- Loading: the `__ANDROID__` branch in `renderer.cpp` uses the relative path `fonts/NotoSansSC-Bold-subset.otf`. On Android, SDL3's `SDL_IOFromFile` maps that to APK assets through `AAssetManager_open`; `SDL_GetBasePath()` returns `NULL`, so it is not used.

## Version

`app/build.gradle` reads the repository-root `VERSION` file and derives the APK metadata:

- `versionName`: `1.0.0` for `release`, or `1.0.0-alpha.1` / `1.0.0-beta.1` / `1.0.0-rc.1` for pre-release stages.
- `versionCode`: `major*100000000 + minor*1000000 + patch*10000 + stage_rank*1000 + build`, with `stage_rank` = alpha 1, beta 2, rc 3, release 4. For `release` the build counter is ignored (treated as 0).

The manifest no longer hardcodes `versionCode` / `versionName`; Gradle supplies both at merge time.

## Input and lifecycle

- Touch: SDL `SDL_EVENT_FINGER_*` events (the input manager supports them, including sticky-ball aiming).
- UI taps: SDL maps single-finger touches to mouse button events, so UI buttons work as-is.
- Back button: `SDL_SCANCODE_AC_BACK` behaves like `Esc` (pause / close settings).
- Backgrounding: focus loss (`SDL_EVENT_WINDOW_FOCUS_LOST`) pauses the game automatically.
- Save data: `SDL_GetPrefPath` resolves to the app's internal storage.

## Known limitations

- Only arm64-v8a is built by default; other ABIs require re-running `build-android.sh` with the matching argument.
- The game uses a 960×700 landscape layout; portrait devices must rotate (the manifest locks `sensorLandscape`).
- CI assembles and uploads a debug APK, but the APK has not been exercised on a physical device.
